Findings:
- `dotenv`: only `package.json`. Not imported by any source file. It was also deduped for `@nuxt/kit@4.6.2` (under `@nuxt/eslint`), where it is an optional peer (`peerDependenciesMeta.dotenv.optional: true`). Kit only loads it as a fallback: `node_modules/@nuxt/kit/dist/index.mjs:290-291` is `if (!_parseEnv) try { const dotenv = await import("dotenv")`, where `_parseEnv = nodeUtil.parseEnv`. That exists on Node ≥24 (`engines.node` is `>=24`), so the fallback never runs. `nitropack`'s `c12` keeps its own nested `dotenv@17.4.2`.
- `@vue/runtime-core`: NOT fully unreferenced. `tsconfig.json:7` has `"types": ["@vue/runtime-core"]`. I removed the direct devDependency and left tsconfig alone. The package stays installed at the same version as a dependency of `vue@3.5.44` → `@vue/runtime-dom` (see `npm ls` below), so the `types` entry still resolves, and typecheck passes (exit 0 below). It is now a transitive dep, not a declared one. Recorded under Noticed, not done.
- `public/fonts/Barlow/`: 19 tracked files (18 `.ttf` + `OFL.txt`, not 17), 1855235 bytes total (sum of `git ls-tree -r -l HEAD public/fonts/Barlow` sizes). Outside the folder itself and evidence/history notes, `git grep "Barlow"` on HEAD finds nothing (exit=1): no CSS, no render script, no config. The untracked `review/` and `.playwright-mcp/` don't mention it either. The only past use was the one-off scratchpad `og.mjs` that rendered `public/og-image.png` for #302 (see `evidence/implementer/2026-11-01/seo-titles-og-image-diff.md`). That script isn't committed, and the PNG is static. Deleted. After the change, `/og-image.png` still serves 200 (21913 bytes) and `/fonts/Barlow/Barlow-Bold.ttf` returns 404 (SSR check below).
- `sass` vs `sass-embedded`: the one `.scss` file is `assets/css/styles.scss`, listed in the `css` array of `nuxt.config.ts`. No vite/nuxt config picks a Sass implementation. PROJECT.md's Decisions table has no sass row. The only past mention is `dev-loop-archive.md` `dependency-upgrade-phase1`, which bumped them as a "matched pair", not a decision to keep both. Vite uses whichever one is installed. I kept `sass` because root `CLAUDE.md` Stack and `doctrine/MEMORY.md` Stack both name "sass", and it is pure JS (no per-platform native binaries). Removed `sass-embedded`. The built CSS still has the compiled nested rules (see SSR check).
- `escapeHtml`: 3 client-side copies confirmed (AboutMe.vue:48, utils/tsCodeLines.ts:8, utils/jsonCodeLines.ts:8). There is also a 4th copy in `server/utils/createPDFAts.ts:50`. It takes `(value: unknown)` and returns `''` for null/undefined, and it is Nitro server code (`server/utils`, a separate auto-import scope from root `utils/`). It is outside the issue's list, so I left it.
